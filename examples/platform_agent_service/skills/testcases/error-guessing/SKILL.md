# 错误推测法

## 何时使用

- 在等价类/边界值/判定表等方法用完之后**做最后一道补充**，专打「方法覆盖不到但实践中常出事」的点；
- 依据是**缺陷模式库**：本系统/同类系统的历史缺陷、评审经验、外部审计（监管检查）的常见问题清单。

## 银行系统高频缺陷模式清单（逐项自查）

**输入与数据**
- 空 / 全空格 / 不可见字符（\t、零宽空格）输入；
- 特殊字符：`'` `"` `<` `&` `%`（SQL/JS 注入位）、emoji、繁体/生僻字姓名；
- 超长字符串（恰在上限与超上限）、前后缀空格是否 trim；
- 金额精度：0.005 四舍五入方向、分位截断、大数（17 位）精度丢失、千分位逗号输入。

**状态与并发**
- 重复提交（双击、重放）、幂等键缺失；
- 并发修改同一记录（乐观锁/悲观锁）、并发扣款双花；
- 超时后重试导致的部分成功（A 成功 B 失败的补偿）。

**时间与时区**
- 账务日切 00:00 前后 1 秒、月末/年末、闰年 2/29、日终批量运行中办理业务；
- 前后端时区不一致（UTC vs 北京时间）导致日期偏一天。

**环境与集成**
- 下游系统返回异常/超时/慢响应（设 3 档：拒绝、超时、返回垃圾数据）；
- 报文重发/乱序、幂等去重；字符编码 GBK↔UTF-8；
- 缓存不刷新（改了限额仍按旧值放行）、旧数据兼容（升级前的历史借据）。

**权限与安全**
- 越权：普通柜员查他人账户、水平越权改单；
- 敏感数据脱敏在日志/报文里是否泄露（卡号、证件号明文）。

## 用法

1. 拿清单逐项对照当前功能点，**命中的疑点直接补 TC-xx**，说明栏写「错误推测：<模式>」；
2. 优先级按业务后果定（资金、账务 > 展示）；
3. 把项目历史缺陷（如审计整改项）追加进本清单——它是活的资产，评审时随产物沉淀。
