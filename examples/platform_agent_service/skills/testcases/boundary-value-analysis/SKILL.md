# 边界值分析法

## 何时使用

- 需求出现「介于 A 与 B 之间」「不超过 N 位」「最多 M 次」「当天/次日」等**任何带边界**的表述；
- 统计表明大量缺陷藏在边界上而非区间中部——等价类划分（[[equivalence-partitioning]]）选出的代表值应优先取边界点；
- 日期/时间边界（月末、闰年 2/29、跨年、账务日切 00:00）在银行系统中是缺陷重灾区，必须单独覆盖。

## 取值策略

对区间 [min, max] 的 5 点基本式（稳健式再加 min-2、max+2）：

```
min-1 | min | min+1 …… max-1 | max | max+1
 无效   有效   有效        有效   有效   无效
```

扩展场景：
- **有序集合/枚举**：取第一个、最后一个、越界位置（第 0 个、第 N+1 个）；
- **长度限制**：0、1、上限-1、上限、上限+1 个字符；
- **金额**：0.00、0.01、精度上限（分位）、单笔上限、上限 ±0.01；
- **日期**：起止日当天、前一天、后一天；账务日切点前后各一秒。

## 设计步骤

1. 从需求中提取全部边界（范围、长度、次数、时间、容量）；
2. 对每个边界按 5 点（或 7 点）取值；
3. 每个取值一条用例，预期结果写明「通过」或「具体报错文案」；
4. 边界值与等价类编号对应标注，纳入设计依据表。

## 银行示例

需求：单笔转账限额 5 万（含）以下免短信验证，5 万以上需短信验证。

- TC-01 转账 49,999.99 → 免短信（max-1）
- TC-02 转账 50,000.00 → 免短信（max，含边界本身，验证「含」字）
- TC-03 转账 50,000.01 → 走短信验证（max+1）
- TC-04 转账 0.01 → 免短信（min+1）；TC-05 转账 0.00 → 拒绝（min，无效）
