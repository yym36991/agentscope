# 状态迁移法

## 何时使用

- 需求中的对象有**状态字段**（申请单：待提交/审核中/已通过/已拒绝/已撤回；借据：正常/逾期/结清/核销）；
- 重点疑点是**非法迁移**：能否跳状态、终态能否被误操作复活、并发操作下状态是否会错乱。

## 方法要点

1. **建状态迁移表**：
   - 状态集 S = {s1…sn}（含初始态与全部终态）；
   - 事件集 E（用户操作、系统定时任务、外部回调、消息驱动）；
   - 迁移：事件 × 当前状态 → 目标状态 + 动作（含不迁移=自环）。
2. **画状态迁移图**后设计两类用例：
   - **合法路径**：覆盖每条迁移边至少一次（N-switch：至少 0-switch=每条边；关键对象建议 1-switch=每对相邻边）；
   - **非法迁移**：对每个状态，尝试触发「表中不存在」的事件（终态对象再提交、已拒绝单再审核），预期=拒绝且状态不变；
   - **并发/重复触发**：同一事件并发两次（幂等性）、事件重放（消息重复投递），预期=只迁移一次。
3. 用例的「操作步骤」写事件+当前状态的前置构造，预期结果写目标状态+副作用（流水、通知、下游同步）。

## 银行示例

借据状态：正常 → (还款) 结清；正常 → (逾期) 逾期；逾期 → (还款) 结清；结清 为终态。

- TC-01 正常→结清：全额还款，预期状态=结清、生成结清证明；
- TC-02 结清态重复还款：预期拒绝（「借据已结清」），不产生第二次扣款；
- TC-03 逾期→结清：含罚息计算正确；
- TC-04 并发两次还款请求：仅一次成功，余额一致（幂等）。

## 与[[scenario-testing]]的区别

场景法走「业务流程链」（多角色多环节），状态迁移盯「单个对象的生命周期」——借据既要在放款场景里走通（场景法），也要单独验证它的每条状态边（本方法）。
