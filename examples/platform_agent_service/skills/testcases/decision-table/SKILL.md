# 判定表法

## 何时使用

- 需求出现「如果…且…则…否则…」的多条件组合规则（费率档位、风控评分、审批流转、权限矩阵）；
- 条件 2–4 个、动作不超过 10 个时收益最大；条件更多时先用[[pairwise-testing]]压缩组合，或先合并等价类减少条件数；
- 评审时判定表本身就是「规则覆盖率」的证据：每列至少对应一条用例，规则无死角。

## 判定表结构

| 组成 | 含义 |
|---|---|
| 条件桩 | 全部输入条件（每条件取值先二值化：Y/N，必要时多值化） |
| 动作桩 | 全部可能的业务结果/动作 |
| 规则（列） | 条件取值的一个组合 + 对应动作 |

**化简规则**：条件取值相同但动作相同的两列（无关条件）可合并，用「—」表示无关项。

## 设计步骤

1. 从需求提取条件桩与动作桩，每个条件二值化（如「金额>5万」→ Y/N）；
2. 生成初始全组合表（n 个条件 → 2ⁿ 列）；
3. 合并无关条件列化简；
4. 每一列（每条规则）至少设计一条 TC-xx，操作步骤按列中条件取值构造输入，预期结果即该列动作；
5. 若需求中某列的动作未定义（规则空洞），**先在用例说明中标记「需求规则缺失，待澄清」**，不要臆造预期结果。

## 银行示例

规则：转账金额>5 万且收款人为新增收款人 → 短信+人脸；金额>5 万且常用收款人 → 短信；金额≤5 万且新增收款人 → 短信；金额≤5 万且常用收款人 → 免验证。

| 条件 | R1 | R2 | R3 | R4 |
|---|---|---|---|---|
| 金额>5万 | Y | Y | N | N |
| 新增收款人 | Y | N | Y | N |
| **动作** | 短信+人脸 | 短信 | 短信 | 免验证 |

→ 4 条用例 TC-01…TC-04，一一对应。发现 R3 与 R2 动作相同但条件不同 → 不可合并（条件都相关），表保持 4 列。
